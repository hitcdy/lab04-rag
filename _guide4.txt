摘要，更新要改图
目独立可增改
本实验的15 道内置问题刻意分成三类（事实/ 多跳/ 全局），就是要让这三种组

4.2 评测指标（必做手算，对照教材式8-9 / 8-10）
为公平对比，三种范式的检索单位（文本块/ 邻域三元组/ 条目）统一映射回「文
档」再计算指标：
Recall@5（式8-9）＝命中的标准文档数÷ 标准文档总数（Top-5 内），衡量「该
找的都找齐了吗」。
MRR（式8-10）＝各题首个命中文档排名倒数的平均：MRR = (1/|Q|) Σ 1/rank，
衡量「找得快不快、排得靠前吗」。
教材手算例：3 题首次命中排名3、1、2 →MRR = (1/3 + 1/1 + 1/2) / 3 ≈0.611。报
告中需另抽3 题手算并与脚本输出核对。
忠实度（对照式8-8 的RAGAS 思想）：人工按1~5 分给答案打分——5 分＝每句
都能在检索到的资料里找到依据；1 分＝主要内容无依据（幻觉）。每种范式抽3
题评分。

def chunk_docs(size=120, overlap=20):
chunks, step = [], size - overlap
for doc_id, text in CORPUS.items():

# 4. 嵌入后端：优先sentence-transformers（教材8.4 节）；
#
未安装/无网络时自动降级为字符3-gram 相似度（流程可跑通，精度有限）
# ============================================================
class Embedder:
def __init__(self, model_name):
self.ok = False
try:
from sentence_transformers import SentenceTransformer
self.model = SentenceTransformer(model_name)
self.ok = True
print(f"[embed] 已加载{model_name}")
except Exception as e:
print(f"[embed] 加载失败（{type(e).__name__}），降级为字符3-gram 相似度（精度
有限）")
def encode(self, texts):
import numpy as np
if self.ok:
return self.model.encode(list(texts), normalize_embeddings=True)
M = np.zeros((len(texts), 512))
for r, t in enumerate(texts):
t = re.sub(r"\s", "", t)
for i in range(max(1, len(t) - 2)):
g = t[i:i + 3] if len(t) >= 3 else t
M[r, zlib.crc32(g.encode("utf-8")) % 512] += 1
n = np.linalg.norm(M[r]) or 1.0
M[r] /= n
return M
def _dedup(scored, k):
docs, seen = [], set()
for doc, s in scored:
# scored 已按分数降序
if doc not in seen:
docs.append(doc)
seen.add(doc)
if len(docs) >= k:
break
return docs

# 5. Vector RAG（教材8.2~8.4 节）：块向量→余弦Top-K →文档序列
# ============================================================
class VectorRAG:
name = "Vector RAG"
def __init__(self, emb):

===== 第 8 页 =====
self.emb = emb
self.chunks = chunk_docs()
self.M = emb.encode([c[1] for c in self.chunks])
def retrieve(self, query, k=5, scope=None):
qv = self.emb.encode([query])[0]
scores = self.M @ qv
order = scores.argsort()[::-1]
hits = [(self.chunks[i][0], float(scores[i])) for i in order]

九、常见问题
Q1：嵌入模型下载不动？
先设镜像再跑：Windows PowerShell 执行$env:HF_ENDPOINT="https://hf-

失败可用--emb 指定本地已下载模型路径，或临时用内置降级方案（字符3-
gram，精度有限，报告须注明）。
Q2：没有LLM API key 能完成作业吗？
能。检索评测（Recall@5 / MRR）全程不需要API；生成与现场抽取环节可在报告
说明用降级方案，或课后在提供API 的环境补跑。
Q3：三元组抽取输出不是合法JSON？
prompt 里已限定「只输出JSON 数组」；参考代码对返回做了截取与解析，失败
会打印原文并跳过。请在报告统计解析失败率——这本身就是GraphRAG 的真实
工程成本（8.7 节）。
Q4：图太碎/ 全连在一块？
抽取粒度按「一篇文档5~10 条」控制；实体要归一（「云大」与「云山大学」合
并为同一节点）。可在报告展示归一前后的图对比。

===== 第 15 页 =====
Q5：WikiRAG 的条目多长合适？
一个条目一个主题（人物/ 课程/ 机构），100~300 字为宜。条目过长会退回「块
太大」的老问题，过短则聚合价值消失。
Q6：Vector RAG 多跳题得分很低（甚至全错）正常吗？
正常——单个文本块装不下跨文档关系链，桥接文档与问题的相似度低（思考题
(1) 追问机理）。但注意：嵌入模型语义泛化强时（如bge 系列），桥接文档也可
能被检回Top-5 末位——此时用任务四⑤的K 敏感性扫描把窗口收窄到1~2，「检
到但排太后」与「根本检不到」的差异会重新显现。
